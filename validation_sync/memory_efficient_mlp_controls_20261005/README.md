# 16384宽度训练的内存优化对照

原32轮大模型训练已记录第4轮完成。独立核验实际进程身份、CPU计算时间推进和Windows进程GPU内存计数：两次约30秒间隔观察均报告4,848,615,424字节共享GPU内存；这不是OOM或硬件极限证明。

新增梯度累积、激活重算和两者结合，保留有效批大小及AdamW更新频率。MSE与Huber各三种实现通过不等长尾批的实际float64梯度及更新检查。原实现、基准包装及三种新实现共完成11次真实成熟样本CPU控制训练；四个包装模型均完成4096条、512宽度、32轮，重载及80条记录前缀一致，三个新实现的未来标签污染检查通过。激活重算权重与原实现逐位一致，梯度累积及组合权重最大差约1.19e-7，需要独立官方评分。

CPU中自动求导保存的非参数张量峰值分别减少75%、97.64%、99.41%；这仅度量该CPU控制里的保存张量，不能当成GPU总内存节省或16384完整拟合的证据。

真实16384宽度GPU单批对照已排队，将等待原完整年度及最终GPU进程结束后执行。首次等待任务读错登记字段并在训练前终止，原代码、RUN和错误均保留；V2已通过实际进程登记和等待检查。三种新实现的15次完整年度训练、3次最终训练及完整官方方案评分仍待后续入口完成，不能以控制试验替代。完整榜仍9822条，最高分0.4510081068915626；未读取测试标签。
