原训练日志只在第1个及每4个epoch结束时输出，不能依据最后一条epoch1日志认定训练停滞。对已核对PID、创建时间和命令身份的原训练进程执行四次只读非暂停采样，观察到2021窗口已经完成3个epoch，当前位于第4/32个epoch；批次位置从第53个推进到第55个。后续20秒观察位于反向传播，进程CPU时间增加20.375秒。

本次只读取当前Python栈和整数循环变量，没有在目标进程执行代码、修改参数、暂停、重启或减少样本。训练源码和诊断工具字节核对一致。该窗口的32个epoch、完整模型、后续窗口和全部推理仍待完成；局部训练损失不是官方分数，不参与采用判断，也不计新增完整模型。

使用官方PyPI py-spy0.4.2 Windows便携二进制，下载包SHA256与PyPI记录匹配，保存在D盘，没有安装或改动Python环境。可按工具receipt中的固定下载URL及SHA复现工具获取。非暂停采样不是原子读取，记录核对epoch、损失列表长度及批次范围的一致性，短时间内相同批次不能单独证明停滞；本次多次观察实际出现了位置推进。工具机制说明见https://github.com/benfred/py-spy#how-can-i-avoid-pausing-the-python-program。
