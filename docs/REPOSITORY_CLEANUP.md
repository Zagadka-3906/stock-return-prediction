# 仓库整理说明

整理日期：2026-10-11。目标是减少当前main的重复导出和过期累计展示，让源码、最新成果与原始验证证据更容易找到。

## 保留什么

保留根目录运行入口、通用源码、基准配置、测试和文档；保留最新37模型候选归档、当前训练评分明细、正式第189/191轮归档及唯一的评分、配置、控制和失败记录。维护者本机的原始数据、最新模型、提交CSV、已核验ZIP和训练恢复所需依赖不在本次归档删除范围。

## 清理什么

1. 相同Git blob的旧导出副本：保留至少一个相同内容路径，原路径和保留路径逐一记录。
2. 较早正式轮次的累计排名HTML、重构报告gzip及其分片：保留第191轮完整累计榜及第189轮归档，旧展示版本可从Git历史取得；其原始科学记录继续保留。
3. 本机可再生成的Python字节码缓存：只在核实的源码目录内删除，不处理原始数据、冻结候选或Python环境。

移除的归档路径记录在[查询清单](../validation_sync/archive_index_20261011.jsonl.gz)。它记录原路径、Git blob、大小、删除理由、相同内容的保留位置或整理前历史文件链接。

## 历史路径怎样查看

```powershell
python tools/find_archive_record.py 'validation_sync/某旧目录/某文件'
```

如果有 `retained_path`，可在当前main中读取相同内容；原路径可以通过返回的 `historical_url`访问，也可以按清单给出的提交号使用 `git show 提交号:原路径`。gzip分片仍应按对应历史清单顺序组装。

旧发布manifest按它的原提交解释，不能把当前分支移除了重复副本理解为历史验证失效。最新候选归档保持完整，不要求通过清理索引拼装。

## 存储与资格

此整理减少当前Git树的文件数与本机发布工作副本占用，不压缩或改写Git历史。已有完整克隆的 `.git`仍保留历史对象；逻辑删除大小不一定等于物理释放量，因为部分文件本来就是硬链接。

整理没有重新训练、评分或推理，也不会把第192轮登记变成完成。当前S、提交CSV和ZIP保持原哈希。实际删除数量及大小以[整理结果](../validation_sync/cleanup140_summary.json)为准。
