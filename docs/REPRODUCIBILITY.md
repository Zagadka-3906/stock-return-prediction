# 复现指南

复现可以指重新训练模型，也可以指从保存权重恢复预测或重新计算某个分数。先确定目标，再收集对应输入，可以避免用一条基准命令误以为复现了另一条历史方案。

## 选择复现层次

| 目标 | 需要的材料 | 当前入口 |
|---|---|---|
| 阅读方法与结果 | Git源码、指标和文档 | 无需原始数据或GPU |
| 跑通固定集成基准 | 原始数据、基础依赖、根目录配方 | [安装与运行](GETTING_STARTED.md) |
| 从已存模型重新预测 | 原生权重、特征顺序、预处理与完整输入 | `predict.py` 或对应冻结推理脚本 |
| 复算训练验证分数 | 验证期预测、相同X/Y面板、原评分器 | `evaluate.evaluate()` |
| 重放37模型历史方案 | 父方案、全部权重、词表、映射、源码、协议和环境 | 指定候选归档与本地完整包 |
| 重新训练基线143 | 完整协议、原始数据、指定版本脚本与环境 | [基线143说明](TRAIN_ONLY_BASELINE143.md) |

原始数据和完整模型二进制包不随普通Git源码克隆分发。部分弃用权重和恢复缓存已清理，保留的分数与配置不能代替那些模型文件。

## 固定集成基准

根目录入口是较容易复现的路线：63基础特征 → 4同伴特征 → 16种子XGBoost与LightGBM辅助模型 → 后处理 → CSV。按[运行指南](GETTING_STARTED.md)操作即可。

`--retrain` 会重新训练配置指向的模型文件；默认则复用已有文件。更换原始数据后，不要沿用没有同源证明的旧缓存或旧模型。若要对比实验，复制配置到新位置，设置独立的模型目录与特征缓存，并记录输入哈希。

## 取得指定冻结快照

只做稀疏检出的读者，可在仓库根目录添加需要的归档：

```shell
git sparse-checkout add validation_sync/TRAIN_only_baseline143_v1_20261011
```

37模型方案的主要快照在：

```text
validation_sync/Actual_consensusFraction101_complete_candidate_sources_and_submission_v1_20261011/
```

归档目录中的源码和证据用于定位具体版本，不代表同时提供所有原始数据、环境与二进制权重。获得完整包后，应先读 `manifest.json`、冻结协议、选择配置和 `verification.json`，逐项建立依赖表。

## 在迁移环境前核对依赖

| 依赖 | 需要确认的内容 |
|---|---|
| 原始数据 | 文件哈希、股票集合、日期范围、标签定义与缺失值 |
| 特征 | 列名、顺序、窗口、Float精度、股票词表和预处理来源 |
| 模型 | 原生格式、SHA256、所属年度或最终模型、库版本 |
| 组合 | 父方案、权重、排序区域、平滑状态和条件分支 |
| 映射 | 收益校准的拟合窗口、参数和应用顺序 |
| 执行环境 | Python、相关库、设备与冻结脚本依赖的绝对路径 |

历史记录中的D/E盘路径只描述原机器。应恢复等价输入或在新版本脚本中显式迁移路径，同时保留原文件。不要修改已绑定哈希的源码，再沿用旧manifest声称文件未变。

## 核验顺序

1. 核对输入与模型哈希，确认文件来自同一个协议和候选。
2. 从原生权重加载模型，检查特征维度、列顺序和词表。
3. 生成全量预测，核对主键、行序、行数和有限值。
4. 与参考CSV进行字节或协议指定精度的比较。
5. 对截断行情重新计算特征和预测，检查对应前缀。
6. 使用原评分器对验证期最终CSV重新计算指标，记录输入范围。

字节相同是比浮点容差更严格的要求，可能受序列化、硬件和依赖版本影响。应如实记录比较方式和误差，不能把近似相等写成逐字节一致。

## 研究记录与执行记录

已有37模型方案记录了原生重载、两次独立全量推理、CSV重放和80日前缀检查；基线143也记录了模型重载、CSV重放和80日特征/预测一致性。这些是历史执行结果，本次文档重写没有重新运行它们。

计算一致性与研究选择的独立性回答不同问题。历史测试反馈、验证区间重复使用和当前结果边界见[研究边界](SELECTION_COMPLIANCE.md)。
